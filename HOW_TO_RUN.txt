=== Setup (one-time) ===

1. Clone the repo and open a terminal in the project folder.

2. Create and activate a virtual environment (recommended so dependencies
   don't collide with anything else on your machine):
   python -m venv .venv
   .venv\Scripts\activate

3. Install dependencies:
   python -m pip install -r requirements.txt

4. Copy the example config/env files and fill in real values:
   copy config.odds.example.json config.odds.json
   copy config.alerts.example.json config.alerts.json
   copy .env.example .env
   - config.odds.json / .env: needs an odds API key. The current pipeline
     uses SharpAPI (https://sharpapi.io) -- set SHARPAPI_API_KEY in .env.
   - config.alerts.json: set email_to to your own address if you want
     run_alerts.py to actually email you.
   - config.json (tracked, not gitignored) controls which sports are
     active (active_sports) -- edit directly, no copying needed.
   All three of the copied files are gitignored, so your real keys/email
   never get committed.

5. Verify the install:
   python -m pytest tests/ -q
   This should show every test passing (test files with pandas/numpy/
   sklearn imports can occasionally fail with an OpenBLAS memory error if
   your machine is low on free RAM at that moment -- that's a system
   resource issue, not a code problem; re-running the file alone usually
   passes).

=== Daily use ===

Shortcut: python run_pipeline.py runs the entire pipeline below (projection
through health check, props, backtesting, governance, staking, CLV) as one
command and prints a pass/fail summary per step. The numbered steps that
follow are the same pipeline broken out individually, useful when you only
want to re-run one stage or need to see a single step's raw output.

1. Open PowerShell in the project folder (activate the venv if you made one).
2. Confirm dependencies are current:
   python -m pip install -r requirements.txt

3. Run the daily weighted projection model:
   python run_daily_projection.py

4. The report will print in the terminal and also save to:
   reports\daily_projection_report.json

5. To append the current projections into the prediction log and build a basic performance summary:
   python run_performance.py

6. To build the current grading summary structure:
   python run_grader.py

7. Grading is automatic now -- run_daily_projection.py (step 4) calls
   bot/merge_results.py at the start of every run, before generating that
   day's new projections. It checks every pick ever recorded in
   logs\pick_odds_log.csv (bot\pick_ledger.py's append-only log of every
   premium/watchlist pick the pipeline has ever actually flagged) against
   its real live result (bot\result_fetcher.py -- ESPN's scoreboard for
   nba/wnba/nfl/ufc/leagues_cup/tennis, MLB Stats API for mlb) and grades
   anything whose game has actually finished. No manual step needed for
   anything the pipeline itself picked. A pick's game that hasn't finished
   yet is simply left alone and re-checked the next time you run the bot.

   To run grading on its own (without a full projection run), or to merge
   a result you want graded that was never an actionable pick (via
   logs\results_ingest_template.csv):
   python run_merge_results.py

   Each newly graded row gets odds and profit_units (flat 1-unit staking)
   looked up from logs\pick_odds_log.csv -- the odds actually available
   when run_market_compare.py flagged the pick as premium/watchlist. A
   pick graded before that price was ever recorded gets a blank
   profit_units rather than a guessed one.

8. To build confidence-bucket reporting from graded results:
   python run_confidence_report.py

9. To generate self-audit upgrade suggestions:
   python run_self_audit.py

10. To email strong NBA/MLB projections:
   python run_alerts.py

11. To compare projections against supplied market lines:
   python run_market_compare.py

   Each game's comparison now also includes spread_comparison and totals_comparison,
   using real point-spread/Over-Under probabilities from the same Monte Carlo game
   simulation, no-vig market pricing, and the same premium/watchlist/pass decision
   gating as moneyline. Requires spreads/totals rows in logs\market_lines.csv
   (fetched automatically alongside moneylines by run_odds_fetch.py); a game with
   no spread or totals rows gets null for those fields instead of a guess.

12. To build the backtesting engine report:
   python run_backtest_summary.py

13. To build calibration, predictive accuracy, market inefficiency, EV optimization, and governance reporting:
   python run_model_governance.py

14. To block stale/example data before using any betting output:
   python pre_bet_health_check.py

15. To export current bet-research candidates:
   python export_bet_candidates.py
   python show_bet_candidates.py
   python betting_readiness_audit.py

   This writes reports\bet_candidates.json and logs\bet_candidates.csv.
   Candidates require fresh odds, matched market comparisons, a premium/watchlist decision tier, and positive expected value.
   If governance is blocked, candidates are labeled research_unproven.
   If the gates fail, the same files are written with mode no_bet and the exact failure reason.
   The readiness audit scores the bot from 0 to 100. A 100 requires fresh real data, exported candidates, passed governance, positive 100+ bet validation, and no fallback data.

16. To generate optional AI advisor recommendations from the latest projection, market, governance, and backtesting reports:
   python run_ai_advisor.py

   Set OPENAI_API_KEY to use the OpenAI Responses API. Without a key, this command writes a local rules-based advisor report.
   Optional: set OPENAI_MODEL to choose the model. The default is gpt-4.1-mini.

17. To build the current player-props output:
   python run_props_engine.py

18. To run the full scheduled pregame email flow:
   python run_scheduled_cycle.py

Player props (NBA and MLB):
- NBA props: python run_player_props.py, then python run_nba_stats.py, then python run_matchup_engine.py, then python run_ranked_props.py
- MLB props: python run_mlb_player_props.py, then python run_mlb_stats.py, then python run_mlb_matchup_engine.py, then python run_mlb_ranked_props.py
- Both write ranked props to logs/ranked_props.csv (NBA) and logs/mlb_ranked_props.csv (MLB), graded A-D by a scale-aware edge/reliability/odds score.
- python run_same_game_parlays.py and python run_correlated_parlays.py combine both sports' ranked props before building parlays.
- python save_best_bets.py combines both sports' top A/B graded props into logs/bets.db, tagged with a sport column.
- python run_settle_props.py settles PENDING props in logs/bets.db against real box scores
  (bot/prop_settlement.py -- MLB via statsapi.mlb.com, NBA via nba_api). A prop only settles
  once its game is confirmed Final; a player who didn't play (DNP, scratch) is voided (profit 0)
  rather than guessed at. Props saved before this existed have no matchup/side recorded and stay
  permanently PENDING -- there's no way to know what game or side they were for after the fact.
  This replaces legacy/settle_bets.py, which picked WIN/LOSS with random.choice() and never
  checked a real result.
- MLB props env vars mirror the NBA ones: MLB_PLAYER_PROPS_MAX_AGE_MINUTES and MLB_PLAYER_PROPS_MAX_EVENTS.

Sportsbook odds API:
- The odds fetcher reads SHARPAPI_API_KEY (env or .env). SharpAPI is the
  sole odds provider -- The Odds API was removed (2026-08-07) after its
  free-tier quota (500 requests/month) ran out under normal use; every
  sport was already silently falling back to SharpAPI by that point anyway.
- Check whether the next run will reuse cache or call the API:
  python api_quota_status.py
- Run: python run_odds_fetch.py
- To avoid over-fetching, run_odds_fetch.py reuses a successful odds snapshot while it is fresh. Default: 10 minutes.
- To intentionally refresh odds before the cache expires, run:
  python run_odds_fetch.py --force
- config.odds.json's "sports" field is a plain list of local sport names
  (["nba", "mlb", ...]) -- every sport in that list gets fetched from
  SharpAPI. Check logs/odds_fetch_status.json's sport_sources field to
  confirm which sports actually returned rows on the last run.
- If odds fetch fails for every sport (no SHARPAPI_API_KEY set, or SharpAPI
  returned nothing for every configured sport), the tool clears current
  market lines and exits non-zero.
- If SharpAPI is down, generate a same-team-name manual odds template:
  python generate_manual_odds_template.py
- Enter fresh verified sportsbook moneylines into odds_a and odds_b, then run:
  python import_manual_odds.py
- Before using any betting output, run:
  python pre_bet_health_check.py
- To export bet-research candidates after the health check passes, run:
  python export_bet_candidates.py
- To print candidates or the no-bet reason in the terminal, run:
  python show_bet_candidates.py
- To get the final 0-100 readiness score, run:
  python betting_readiness_audit.py
- After a graded loss, export_bet_candidates.py blocks new picks with a loss cooldown. That cooldown is intentional.
- Do not use picks when the pre-bet health check reports stale odds, stale projections, failed odds fetch, no current market lines, or no actionable matched edges.

Current model status:
- NBA: weighted model with form, offense, defense, pace, rest, injuries, market comparison, and governance
- MLB: weighted model with form, starters, bullpen quality, bullpen fatigue, freshness, splits, scoring, run prevention, market comparison, and governance
- WNBA: weighted model with form, offense, defense, pace, rest, market comparison, and governance. No player-props layer yet (moneyline/team-level only). Injury context has no live data source and is held neutral (no WNBA equivalent of the NBA's official injury-report PDF exists yet).
- NFL: weighted model with form, offense, defense, turnover differential, rest, a real ESPN injury feed, market comparison, and governance. No player-props layer yet (moneyline/team-level only). Points-allowed/points-for come from season standings and are placeholder league-average values until real games are played this season; the injury weighting will need recalibration once real regular-season injury reports (much shorter than the current preseason camp-report noise) start flowing. The odds mapping targets the regular season (americanfootball_nfl) by default -- preseason games use a separate sport key (americanfootball_nfl_preseason) not wired in by default.
- UFC: weighted fighter-vs-fighter model (sports/ufc.py) -- structurally different from every other sport here (no teams, no home/away, no scoring to simulate). Uses win-loss record, finish rate (TKO+submission share of wins), reach/height differential, age, and career fight count, pulled from ESPN's MMA scoreboard and per-fighter bio endpoints. Moneyline only -- MMA has no real spreads/totals market. Recent-form/days-since-last-fight is deliberately not included; ESPN's public fight-history endpoint didn't return usable per-fight dates during development, so it stays out rather than being faked. Odds come from SharpAPI (league=ufc).
- Leagues Cup (sports/leagues_cup.py): the MLS/Liga MX summer cup tournament, drawing teams from two different leagues. Combines a weighted team-strength score (recent form, attack, defense, home advantage from real MLS/Liga MX season standings) with a real double-Poisson goal-scoring model for actual win/draw/loss probabilities -- not the shared sigmoid every other sport uses, since soccer has three real outcomes, not two. Team goal rates are shrunk toward their league average by sample size (same style as MLB's platoon-split shrinkage) rather than trusted outright -- caught live: an unshrunk 3-game sample drove a 95% win probability off noise before this was added. Moneyline only for now: the Draw price is reported (poisson_draw_probability on every game) but not yet compared against the market, since market_lines.csv is a 2-way schema and Draw is a genuine third outcome -- see README for the tradeoff.
- ATP/WTA tennis (sports/tennis.py, tennis_atp/tennis_wta): a real maximum-likelihood Bradley-Terry player rating fit against every singles result each tour has played so far this season (fit_player_ratings()), blended with current real ATP/WTA ranking points as a secondary/fallback signal. This is the tennis analog of Leagues Cup's Poisson regression -- same reasoning, verified the same way (see README's "Why regression, here specifically"). No teams, no home/away, moneyline only. Also fits separate per-surface (hard/clay/grass) ratings and uses one when the match's surface can be inferred and both players have enough real matches on it -- ESPN exposes no surface field, so surface is guessed from the tournament name (guess_surface()) and falls back to the pooled all-surface rating when unrecognized or under-supported (see README's tennis bullet for the real graded loss -- Marta Kostyuk over Iga Swiatek -- that this was built to fix). Odds come from SharpAPI's fixed atp/wta league keys.
- NHL (sports/nhl.py): weighted model with form, home-ice advantage, team strength, offense (goals-for/game + power-play goals), defense (goals-against/game + real save percentage), penalty-minute discipline, rest (near-daily schedule, back-to-backs matter -- same treatment as NBA's rest scale, not NFL's weekly one), and a real ESPN injury feed (sports/nhl_injuries.py) weighted heaviest for goalies. Offense/defense strength comes from fit_team_ratings() -- a maximum-likelihood Poisson joint fit (same simplified Dixon-Coles approach as Leagues Cup) across the season's full real results, correcting for opponent quality; falls back to naive per-game rates when there isn't enough real data to fit yet (rating_source on every game says which ran). Caught live: ESPN's NHL scoreboard silently truncates a wide dates range query to ~25 events no matter how wide the range is, so _fetch_match_results() walks the season day by day instead of one range call (unlike every other sport here). Also caught live: a real fit's attack/defense values aren't zero-centered (mean attack ~0.56, not 0), so converting a rating back to a per-game rate uses the fit's own real average as the reference point (_rating_reference_point()) rather than a separate league-average-goals constant -- multiplying by that constant on top double-counted the baseline and produced an impossible ~7 goals/game before the fix. poisson_home/away_win_probability collapses a real Poisson scoreline grid to 2 outcomes since NHL games always have a winner (tied-regulation mass split by home-ice advantage, a documented simplification -- not a real OT/shootout model). No player-props layer yet (moneyline/team-level only). Off-season right now (next real game is the 2026-27 season, ~mid-September preseason) -- returns 0 games until then, same as NBA's current off-season state; all underlying fetches (team stats, injuries, standings, and the regression fit itself: 32 real teams off 764 real 2025-26 results) verified live regardless. Odds come from SharpAPI (league=nhl).
- NCAAB (sports/ncaab.py): weighted model with form, home-court advantage, team strength, offense/defense, a rebounds/turnovers matchup factor, and rest. D1 has ~365 real teams across ~31 real conferences, not a small fixed count -- get_league_scoring_stats() walks every conference, confirmed live covering all 365. Offense/defense strength comes from fit_team_ratings() -- a regularized least-squares regression jointly fit across the season's full real game scores, the continuous-score analog of Leagues Cup's/NHL's Poisson regression (squared-error loss instead, since points aren't Poisson-appropriate the way low-scoring goals are) and the same underlying idea real adjusted-efficiency systems like KenPom/Sagarin use; falls back to real conference-standings points-for/against averages when there isn't enough real data to fit yet (rating_source on every game says which ran). Two real bugs caught live: a raw day-by-day fetch pulled in ~728 "teams" (real D1 teams' non-conference buy games against non-D1 opponents), breaking the fit (home-court advantage inflated to ~14 points) until filtered to a known-D1 roster via _filter_to_known_teams(); and at ~365 teams (731 parameters), a naive un-vectorized, no-analytic-gradient fit took 5+ minutes and still failed to converge, fixed with an analytic gradient and numpy vectorization (seconds, not minutes). The L2 regularization constant had to be swept and calibrated live too -- it turned out to control how much systematic home-court signal leaks into the model's unregularized home-advantage term (swept 2.29 to 49.85 points across the tested range) -- landing on a value that puts home-court advantage (~3.75 pts) and average scoring (~72 ppg) both in real published D1 ranges. fit_home/away_win_probability converts the fit's predicted margin to a win probability via the normal CDF using the model's own real residual std dev (~10-11 pts), not a discrete scoreline grid, since basketball scoring is high enough to be normal-ish rather than Poisson-ish. No injury factor -- ESPN's college-basketball injury feed came back genuinely empty at development time and its shape couldn't be confirmed, so injury context stays neutral rather than being built against something unverified (same honest gap as WNBA). No pace factor -- no accessible college equivalent of nba_api's league-wide pace data. Off-season right now (season starts ~Nov 2) -- returns 0 games until then; underlying fetches (including the regression fit itself: 365 real teams off 5,767 real 2025-26 results) verified live regardless. Odds come from SharpAPI (league=ncaab).
- NCAAF (sports/ncaaf.py): a close port of sports/nfl.py -- ESPN's college-football statistics endpoint uses the exact same field names as its NFL equivalent (totalPointsPerGame, yardsPerGame, turnOverDifferential, thirdDownConvPct), confirmed live (TCU: 30.7 ppg, 421.5 yards/game). Form, home-field advantage, team strength, offense, defense, turnover differential, rest (NFL's weekly cadence, not basketball's near-daily one), and a real ESPN injury feed (sports/ncaaf_injuries.py, same shape as NFL's -- unlike NCAAB, this feed is real and populated). FBS has ~11 real conferences, not NFL's 2 -- get_league_scoring_stats() walks every conference, confirmed live covering 124 real teams. Season starts in ~3 weeks (Aug 29) -- odds are already posted (confirmed live via SharpAPI, league=ncaaf).
