=== Setup (one-time) ===

1. Clone the repo and open a terminal in the project folder.

2. Create and activate a virtual environment (recommended so dependencies
   don't collide with anything else on your machine):
   python -m venv .venv
   .venv\Scripts\activate

3. Install dependencies:
   python -m pip install -r requirements.txt

4. Copy the example config/env files and fill in real values:
   copy config.odds.example.json config.odds.json
   copy config.alerts.example.json config.alerts.json
   copy .env.example .env
   - config.odds.json / .env: needs an odds API key. The current pipeline
     uses The Odds API (https://the-odds-api.com) -- set THE_ODDS_API_KEY
     in .env, or put the key directly in config.odds.json.
   - config.alerts.json: set email_to to your own address if you want
     run_alerts.py to actually email you.
   - config.json (tracked, not gitignored) controls which sports are
     active (active_sports) -- edit directly, no copying needed.
   All three of the copied files are gitignored, so your real keys/email
   never get committed.

5. Verify the install:
   python -m pytest tests/ -q
   This should show every test passing (test files with pandas/numpy/
   sklearn imports can occasionally fail with an OpenBLAS memory error if
   your machine is low on free RAM at that moment -- that's a system
   resource issue, not a code problem; re-running the file alone usually
   passes).

=== Daily use ===

Shortcut: python run_pipeline.py runs the entire pipeline below (projection
through health check, props, backtesting, governance, staking, CLV) as one
command and prints a pass/fail summary per step. The numbered steps that
follow are the same pipeline broken out individually, useful when you only
want to re-run one stage or need to see a single step's raw output.

1. Open PowerShell in the project folder (activate the venv if you made one).
2. Confirm dependencies are current:
   python -m pip install -r requirements.txt

3. Run the daily weighted projection model:
   python run_daily_projection.py

4. The report will print in the terminal and also save to:
   reports\daily_projection_report.json

5. To append the current projections into the prediction log and build a basic performance summary:
   python run_performance.py

6. To build the current grading summary structure:
   python run_grader.py

7. To merge completed game results from the template into graded results:
   python run_merge_results.py

   Each newly graded row now also gets odds and profit_units (flat 1-unit
   staking), looked up from logs\pick_odds_log.csv -- the odds actually
   available when run_market_compare.py flagged the pick as premium/
   watchlist (bot\pick_ledger.py). A pick graded before that price was
   ever recorded gets a blank profit_units rather than a guessed one.

8. To build confidence-bucket reporting from graded results:
   python run_confidence_report.py

9. To generate self-audit upgrade suggestions:
   python run_self_audit.py

10. To email strong NBA/MLB projections:
   python run_alerts.py

11. To compare projections against supplied market lines:
   python run_market_compare.py

   Each game's comparison now also includes spread_comparison and totals_comparison,
   using real point-spread/Over-Under probabilities from the same Monte Carlo game
   simulation, no-vig market pricing, and the same premium/watchlist/pass decision
   gating as moneyline. Requires spreads/totals rows in logs\market_lines.csv
   (fetched automatically alongside moneylines by run_odds_fetch.py); a game with
   no spread or totals rows gets null for those fields instead of a guess.

12. To build the backtesting engine report:
   python run_backtest_summary.py

13. To build calibration, predictive accuracy, market inefficiency, EV optimization, and governance reporting:
   python run_model_governance.py

14. To block stale/example data before using any betting output:
   python pre_bet_health_check.py

15. To export current bet-research candidates:
   python export_bet_candidates.py
   python show_bet_candidates.py
   python betting_readiness_audit.py

   This writes reports\bet_candidates.json and logs\bet_candidates.csv.
   Candidates require fresh odds, matched market comparisons, a premium/watchlist decision tier, and positive expected value.
   If governance is blocked, candidates are labeled research_unproven.
   If the gates fail, the same files are written with mode no_bet and the exact failure reason.
   The readiness audit scores the bot from 0 to 100. A 100 requires fresh real data, exported candidates, passed governance, positive 100+ bet validation, and no fallback data.

16. To generate optional AI advisor recommendations from the latest projection, market, governance, and backtesting reports:
   python run_ai_advisor.py

   Set OPENAI_API_KEY to use the OpenAI Responses API. Without a key, this command writes a local rules-based advisor report.
   Optional: set OPENAI_MODEL to choose the model. The default is gpt-4.1-mini.

17. To build the current player-props output:
   python run_props_engine.py

18. To run the full scheduled pregame email flow:
   python run_scheduled_cycle.py

Player props (NBA and MLB):
- NBA props: python run_player_props.py, then python run_nba_stats.py, then python run_matchup_engine.py, then python run_ranked_props.py
- MLB props: python run_mlb_player_props.py, then python run_mlb_stats.py, then python run_mlb_matchup_engine.py, then python run_mlb_ranked_props.py
- Both write ranked props to logs/ranked_props.csv (NBA) and logs/mlb_ranked_props.csv (MLB), graded A-D by a scale-aware edge/reliability/odds score.
- python run_same_game_parlays.py and python run_correlated_parlays.py combine both sports' ranked props before building parlays.
- python save_best_bets.py combines both sports' top A/B graded props into logs/bets.db, tagged with a sport column.
- python run_settle_props.py settles PENDING props in logs/bets.db against real box scores
  (bot/prop_settlement.py -- MLB via statsapi.mlb.com, NBA via nba_api). A prop only settles
  once its game is confirmed Final; a player who didn't play (DNP, scratch) is voided (profit 0)
  rather than guessed at. Props saved before this existed have no matchup/side recorded and stay
  permanently PENDING -- there's no way to know what game or side they were for after the fact.
  This replaces legacy/settle_bets.py, which picked WIN/LOSS with random.choice() and never
  checked a real result.
- MLB props env vars mirror the NBA ones: MLB_PLAYER_PROPS_MAX_AGE_MINUTES and MLB_PLAYER_PROPS_MAX_EVENTS.

Sportsbook odds API:
- The odds fetcher reads THE_ODDS_API_KEY, SPORTSBOOK_ODDS_API_KEY, or config.odds.json.
- Check whether the next run will reuse cache or call the API:
  python api_quota_status.py
- Run: python run_odds_fetch.py
- To avoid burning API quota, run_odds_fetch.py reuses a successful odds snapshot while it is fresh. Default: 10 minutes.
- To intentionally refresh odds before the cache expires, run:
  python run_odds_fetch.py --force
- If SHARPAPI_API_KEY is set (see .env.example), a sport that fails against
  The Odds API (quota exhausted, outage, bad key) automatically falls back
  to SharpAPI for that sport alone instead of failing the whole run. Check
  logs/odds_fetch_status.json's sport_sources field to see which provider
  each sport actually came from on the last run.
- If odds fetch fails for every sport (no SharpAPI key, or SharpAPI also
  failed), the tool clears current market lines and exits non-zero.
- If both APIs are down, generate a same-team-name manual odds template:
  python generate_manual_odds_template.py
- Enter fresh verified sportsbook moneylines into odds_a and odds_b, then run:
  python import_manual_odds.py
- Before using any betting output, run:
  python pre_bet_health_check.py
- To export bet-research candidates after the health check passes, run:
  python export_bet_candidates.py
- To print candidates or the no-bet reason in the terminal, run:
  python show_bet_candidates.py
- To get the final 0-100 readiness score, run:
  python betting_readiness_audit.py
- After a graded loss, export_bet_candidates.py blocks new picks with a loss cooldown. That cooldown is intentional.
- Do not use picks when the pre-bet health check reports stale odds, stale projections, failed odds fetch, no current market lines, or no actionable matched edges.

Current model status:
- NBA: weighted model with form, offense, defense, pace, rest, injuries, market comparison, and governance
- MLB: weighted model with form, starters, bullpen quality, bullpen fatigue, freshness, splits, scoring, run prevention, market comparison, and governance
- WNBA: weighted model with form, offense, defense, pace, rest, market comparison, and governance. No player-props layer yet (moneyline/team-level only). Injury context has no live data source and is held neutral (no WNBA equivalent of the NBA's official injury-report PDF exists yet).
- NFL: weighted model with form, offense, defense, turnover differential, rest, a real ESPN injury feed, market comparison, and governance. No player-props layer yet (moneyline/team-level only). Points-allowed/points-for come from season standings and are placeholder league-average values until real games are played this season; the injury weighting will need recalibration once real regular-season injury reports (much shorter than the current preseason camp-report noise) start flowing. The odds mapping targets the regular season (americanfootball_nfl) by default -- preseason games use a separate sport key (americanfootball_nfl_preseason) not wired in by default.
- UFC: weighted fighter-vs-fighter model (sports/ufc.py) -- structurally different from every other sport here (no teams, no home/away, no scoring to simulate). Uses win-loss record, finish rate (TKO+submission share of wins), reach/height differential, age, and career fight count, pulled from ESPN's MMA scoreboard and per-fighter bio endpoints. Moneyline only -- MMA has no real spreads/totals market. Recent-form/days-since-last-fight is deliberately not included; ESPN's public fight-history endpoint didn't return usable per-fight dates during development, so it stays out rather than being faked. Odds come from The Odds API (mma_mixed_martial_arts) with the same SharpAPI (league=ufc) fallback every other sport uses.
- NHL/NCAAB/NCAAF: scaffold only
